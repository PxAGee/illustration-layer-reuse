# Photoshop 自动化防错经验

这些来自一次 Windows Photoshop 26.3 的实际流程。已确认的是产物故障；对具体 API 内部原因不能做超出证据的断言。换版本先做小样，不直接复制旧脚本。

## 图层身份与蒙版

- 曾发现 7 条不同 AI 补片记录共用同一个图层 ID，实际树中只剩一个补片。不能只信函数返回值、名称或旧清单。
- 每次导入/复制比较操作前后的真实图层树，必须出现预期的新 ID；记录 ID 的对象须属于目标文档。新补片之间不应误用同一 ID。检查层数、父组、边界、可见性及蒙版。
- 跨文档操作、通道复制及文档关闭后，重新指定目标文档，按 ID 重新定位图层，再建蒙版。不得假设 activeDocument/activeLayer/activeChannels 没变。
- 有蒙版的层不再直接“建立蒙版”。先确认是更新选区/蒙版还是替换像素；保留原蒙版，避免误应用或删除它。
- 通道操作后恢复色彩分量通道。用小样验证选区是否为空、是否真的加载目标层蒙版、是否把全部画布误当选区。
- 暂存通道只在确认属于本任务且已不再引用时清理；大型任务注意通道容量、内存和暂存盘，不能无限积累中间文档。

## 导入对齐

- 跨文档复制和粘贴都可能带来状态或位置问题；换一种方法不等于已解决。
- 记录输入画布尺寸、内容 bounds、目标裁片原点和变换。粘贴后读取实际 bounds，与预期坐标比较并校正。对象自动居中会造成“整体差不多、缺口全错位”。
- 对原可见像素禁止未经授权缩放、旋转；AI 补片可按记录变换，但须目视验证边界与纹理。
- 先导出一张局部预览验证新层身份、位置和蒙版，成功后再跑完整对象。

## 执行与保存

- Photoshop 写操作串行；上一个进程完成前不要启动第二个 COM 调用。遇到 busy/RPC 错误先检查前一个操作状态。
- 命令进程退出码为 0 不能证明 JSX 成功；检查返回字符串、异常、文件时间、实际图层树与产物。
- ExtendScript 能力取决于版本，不能默认现代 JavaScript API（如全局 JSON）均可用。
- 用目标文档和本任务临时文件检查；不执行全局历史清空、不关闭用户其他文档，不覆盖原图。
- 脚本按小段执行并写检查点。故障后恢复最近通过状态，保留诊断信息；不要反复运行已完成的全量建层脚本。

## 最小成功证据

新图层 ID 唯一且存在 → 父组正确 → bounds 对齐 → 蒙版非空且区域正确 → 独立预览通过 → 合成不退化 → 保存重开状态相同。

只有全部通过才把此对象标为完成。此文档不附带旧项目的自动化脚本，因为其故障与具体坐标不能安全推广到任意插画。
