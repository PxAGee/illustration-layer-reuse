# 本次对话复盘：事实、判断与防止重演

## 已确认的结果与未完成部分

最终修订 PSD 为 4168×6252、500 ppi、8 位 CMYK，25 个空间组、55 个原像素分片；最终同色彩条件比较为 0 像素差异。原图参考关闭，拆分原像素仍能重组。以上证明原位还原，没有证明每件对象都提取干净。

独立人物、葡萄预览仍有饰物/指缘残留、补片接缝等问题。对话最后明确承认其未达到完整无缝复用；不能把本流程包装成已经成功解决所有难点的自动化方案。

## 问题与避免方式

| 出现的问题 | 已确认事实或判断边界 | 下次怎么避免 |
| --- | --- | --- |
| 先做 AI 完整素材，整体大小结构走样 | 用户指出重组不像原图；AI 重绘不能保证原位还原 | 可见源像素锁定坐标；先构图与遮挡表，AI 只补缺口 |
| 把前中后景当成简单分组 | 手与葡萄、发丝与胸饰、花枝与纱有局部穿插 | 对象先建遮挡依赖，循环穿插拆片，不强求一对象一层 |
| 合成验收取代独立验收 | 0 差异通过，但单独人物和葡萄仍有空洞/残片 | A 原构图、B 独立素材分别记状态；两者通过才能完成 |
| 源像素分区正确但对象边缘错 | 每像素恰好一次仍包含不属于对象的装饰碎片 | 覆盖统计只查遗漏重复；语义归属必须看单独预览 |
| 补片图层身份错绑 | 7 条补片清单共用一个 ID，真实树缺少多层 | 导入前后比真实图层树，验证唯一 ID/父组/bounds/蒙版 |
| 把错误归因得过于肯定 | 错绑已确认，但不能仅凭现象断定某个 API 的内部缺陷 | 区分观察与推测；先最小复现，再修状态管理 |
| 全人物 AI 底图不对纹理 | 发丝/衣纹拼接明显；换整张底图也没自动解决 | 缺口按头发、衣料、手腕拆开局部修，保留邻近上下文 |
| 粘贴位置与蒙版错开 | 流程中需要纠正导入定位；不能把“导入成功”当对齐 | 输入 bounds、裁片坐标、输出 bounds 三方核对 |
| 残留底色、伪透明与光晕 | 合并 JPG 的纱云已混底；alpha 存在仍可能有脏边 | 白/黑/目标底色检查；记录原位外观与净透明重建的区别 |
| 高像素画布掩盖 AI 低原生细节 | 新 AI 为 1024×1536，再放大到原画布 | 分别报告画布、ppi、原像素、AI 原生尺寸及放大倍率 |
| 过早批量导出与反复全量检查 | 缺陷在输出大量素材后才发现，多次刷新全套 | 代表对象先验收；只重导改动对象与受影响组合 |
| 状态信息分散，需要多次“继续” | 脚本、清单、补片身份与完成状态不一致，续接反复查找 | 单一清单+短进度文件；记录剩余缺陷和下一步，不靠聊天记忆 |
| 报告或文件名比实际质量更乐观 | “AI补全/完整复用”文件名不能证明补全完成 | 命名与两项验收状态一致；未通过标“待修”，不靠免责声明包装完成 |

## 节省 token 的有效方向

减少重复读取、全量重跑、盲试和无效生图，通常比把提示词缩成几个关键词更有用。技能本身也占上下文，不能保证固定节省比例；详细故障文档按需读取，正常任务只加载短入口和当前状态。

本次没有足够的逐操作计费记录来量化具体节省金额或比例，因此不提供虚构的节省数字。
